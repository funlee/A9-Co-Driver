# 运行资源与来源

默认构建直接使用仓库内 `app/src/main/assets/` 的文件，不依赖本机私有目录，也不需要下载或解包原参考 APK。

| 资源 | 用途 |
|---|---|
| `data/routes.txt` | 256 条内部记录（完整保留参考 APK 的 202 条，另有 54 条空跑法） |
| `data/map-rules.tsv` | 251 个当前国服赛段、内部索引及识别别名 |
| `data/progress.lib` | 58 个数字字形模板；这是文本字库，不是二进制库 |
| `data/forms.json` | 七类任务的配置项、选项与默认值 |
| `data/provenance.json` | 参考 APK 摘要、来源说明、发布时资源摘要和验证范围 |
| `lua/shared.lua`、`utilities.lua`、`workflows.lua` | 适配后的共享状态、工具和任务运行逻辑 |
| `lua/multiplayer_up.lua`、`multiplayer_down.lua`、`cup.lua`、`special.lua`、`club.lua`、`career.lua`、`daily.lua` | 适配后的各赛事模块 |
| `lua/bootstrap.lua`、`multiplayer_current.lua` | 本项目编写的宿主适配、队列调度和现行多人赛流程 |
| `licenses/` | LuaJava、jnigen 等依赖许可原文 |

维护者于 2026-11-07 确认已获得提取及适配资源的公开再分发授权，并将这些运行资源纳入本项目开源范围，随项目采用根目录 MIT 许可。资源的提取来源继续保留，不将其表述为全部独立原创。此说明记录维护者的授权确认，不代表对原 APK 或游戏本体授予许可。

提交新资源时同步更新 `tools/audit-public.py` 的明确清单；修改已有资源时更新 `provenance.json` 对应摘要及验证说明。审核脚本检查资源是否齐全，并可比较 APK 内资源与源码是否逐字节一致。克隆者可运行 `sh tools/check-core.sh` 验证随库资源和调度逻辑。

`tools/prepare_assets.py` 保留为可选的历史转换工具：它只读取本机 `private/analysis/`，输出到 `private/assets/`，不会覆盖随库资源或参与默认构建。重新转换不是运行助手的前置步骤。

### 杯赛位置缓存（2026-11-09）

共享选择器只在同一次运行且位置未变时复用杯赛图片。新任务或配置位置改变会删除该项目的旧缓存，先选择配置的位置，再重新截图。修正首位坐标、负数末位判断、重试时丢失位置参数及重新定位后的下标偏移；非法位置直接报错。

9 项合成检查直接执行实际 utilities.lua；MuMu 上另执行选择器专用测试，配置 3 进入左起第三个“每日车辆战利品”，未调用开赛流程。真实菜单验证仅覆盖此次位置 3，不能据此声明其他位置或完整杯赛循环已验收。

### 收益统计与悬浮面板（2026-11-09）

- 结算页先确认“比赛奖励、你的用时、总金币”上下文，再分别读取归一化游戏画面的总金币与右上经验数字区域。名人堂必须有 + 前缀，百分比、混合数字及不完整读数均拒绝；充值比例不参与计算。
- 对不同的新截图执行稳定性确认，继续按钮可用后再记录。每局金币和名人堂分别去重，允许补齐另一项；失败保持 -1／未识别，不伪造 0。多人流程在通用关闭提示前处理奖励；原赛事结算循环也接入同一读取器，且必须先见到本次比赛画面，收益只在原流程确认返回后入账。
- 累计收益、已识别场次数和最近一局数值进入原子任务记录；兼容没有收益字段的旧记录。旧任务收益不追补估值，重启后旧结算不能重复入账。
- 悬浮窗默认显示精简统计，详情包含名次统计口径、收益覆盖率、最近一局和原有执行信息；可折叠、拖动吸边并记住位置，选车和结算时自动避让。
- 实际 OCR 回放：普通账号 4800／189，充值账号 2880／207；图中 90%、+10%、+25%、系列赛 +48、4976、5458 和奖励卡片 88888 不计入。充值截图只裁掉外部云手机工具栏及黑边，再归一化游戏区域；原图保留在私有目录。回放及合成检查不代表真实连续比赛已完成验收。

### 车库筛选（2026-11-09）

- 旧逻辑用固定颜色等待且不检查等待结果，随后盲点选项；性能分、排序箭头坐标已偏离当前控件，已选“拥有”也可能破坏旧等待条件。

### 赛事流程边界与每日战利品（2026-11-09）

- 主要玩法分为杯赛、特殊赛事、多人赛事；杯赛再分每日战利品和其他杯赛。保持独立任务配置与流程入口：`daily.lua`、`cup.lua`、`special.lua`、`multiplayer_current.lua`。队列只负责调度，各流程自行决定进场、选车、地图识别、结算和返回条件。
- 截图、OCR、输入、跑图和每局收益记录可复用，但共享收益读取器不依赖多人菜单分类。每日战利品使用独立 `DailyEventUi`，地图从加载页赛事标题下方读取，连续两帧确认后绑定参考路线。未确认或无有效路线时沿用左划兜底。
- 每日战利品结算分别处理单人结果、金币/经验奖励、图纸和红币兑换；返回赛事连续确认后才记为完成。奖励页出现三倍金币广告时仅点击“错失机会”，不点击“观看广告”。每日战利品显式使用自身大字金额布局，广告出现前后均适用；金额按每局新截图稳定识别，广告倍增金额不计入；退出按钮可用后仍允许等待读数，超时字段保持未识别。
- 前三率的分子、分母只统计多人赛。杯赛（含每日战利品）、特殊赛事只累计自身完赛与已识别收益，不参与多人名次统计。
- 合成检查覆盖结算页面跳过、重复、临时返回、未知页面不点击、广告退出、地图去除旧值，以及五种任务交替时的动态收益与多人前三率。私有截图回放覆盖每日战利品和普通/充值账号奖励布局。

- 截屏线程复制 ImageReader 平面期间与关闭/尺寸调整共用锁，防止任务结束时缓冲区先释放引起 native 崩溃。

- 0.1.37 最终实跑：每日战利品位置 3 → 喧闹铁路（8 条参考动作）→ 结果/奖励 → 跳过广告 → 返回赛事 → 单局上限停止。该局金币动画 2787→3200，稳定后实际记录 3200／105，完赛及返回各 1，名次统计 0；无人工赛中介入。此前调试局另覆盖图纸与红币兑换。此验证不扩展为其他杯赛、特殊赛事或连续长跑已验收。

### 三任务验收发现与修复（0.1.38）

- 维护者配置每日战利品 10 局、大师 20 局、世界 30 局。自动识图重跑阶段每日战利品实际完成 4 局后缺票，自动进入大师；大师首局第 2 名，收益 4800／189，但三倍广告页阻断了返回。该轮未通过完整验收，世界任务尚未执行；维护者要求等油票恢复后再启动实跑。
- 修复“每辆用一次＋点击选车”成功后未记录已用配置项，以及循环末项重复使用的问题。允许配置中显式重复的车号，按配置项轮换；全部不可用时退出，不无限重试。真实 Lua 合成检查覆盖重复车号、无油跳过、整轮用完重置和单车模式。
- 每日缺票向队列返回 `noTicket`，显示“跳过剩余场次”，不再误报配置场次全部完成。队列结束一个项目时清理旧赛事的待开赛/收益状态，防止进入多人后开赛次数重复增长。
- 多人奖励流程独立处理“错失机会”，共用的识别能力仅提供白名单退出按钮及颜色状态，不点击广告。金额布局仍由赛事调用方显式指定；每日大字、多人普通/充值字体不因广告出现而互换。
- 新增实际多人广告奖励图回放（4800／189，广告报价 14400 排除），及实际多人 Lua 的广告退出检查。修复版本通过离线检查、构建和截图回放，尚未重新实跑。

### 每日战利品调度（0.1.39）

- 每日一次为单个任务的可选项，默认关闭。任务有稳定 `taskId`，完成日期独立保存于 `daily-task-history`，编辑名称/参数、队列循环及重建运行器均不清除记录。
- 只有确认完赛达到配置场次才记录当天完成；缺油、缺票、手动停止和总完赛上限提前结束均不冒充任务完成。完整完成时即同步保存日期，不依赖整轮队列结束。
- 使用设备本地日期/时间；固定跳过区间为 `[00:00,00:30)`。队列入口、每日任务每局准备及开跑前检查；跨零点时允许当前比赛正常结算，后续场次跳过。下一天 00:30 起重新允许任务执行。
- `DailyTaskPolicy` 只负责每日任务规则，`daily.lua` 提供跳过原因，队列负责推进；其他杯赛、特殊赛事和多人不套用该策略。
- 离线验证包含边界、跨天、完成/部分完成、独立任务、重建状态、实际 Lua 跨零点停止开跑和跳过后继续下一任务。未启动游戏实跑，等待维护者通知。
- 模拟器离线检查通过真实偏好存储写入/重建读取、任务标识稳定性及配置项存在性；已安装 0.1.39，保留用户原配置并停留待命。未启动比赛。
